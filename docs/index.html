TamaClaudchi

A dashboard for watching several Claude Code agents at once. One Python file, plain HTML/CSS/JS, stdlib only, no build step, no dependencies, no external assets. This is the developer guide; see the README to run it.

Shape

server.py       aggregation + HTTP (stdlib http.server)
web/index.html  the page
web/app.js      all rendering and interaction
web/style.css   one token set, light + dark
hooks/          optional Claude Code hook script

The frontend polls /api/state every 600 ms; the server caches a built board for 250 ms. Those two numbers are the lag between an agent changing state and the card saying so, so keep the cache below the poll.

tmux list-panes + pswhich pane each agent pid lives in

~/.claude/tasks/<sid>/*.jsontask list and dependency edges
~/.claude/agent-events/<sid>.jsonlhook events (optional)

Written state, all user-owned and written atomically: agent-manager-names.json (renames), agent-manager-artifacts.json (pinned files), agent-manager-spawns.json (who launched whom).

Endpoints

All gated on the token — no exceptions.

Security model

One shared token gates every /api/* request. That single mechanism defeats CSRF, DNS-rebinding and shared-host snooping, chosen over layering Origin checks + CORS + content-type sniffing. It rides in the URL fragment (never sent on the wire) and comes back as X-Auth-Token.

Non-negotiable when changing this code.
  • Anything reaching tmux takes an allowlist, never free text: ALLOWED_KEYS, CYCLE_MODES, _MODEL_ID_RE, the --resume pattern, artifact extensions. Validate before the pane lookup.
  • read_artifact and /api/chat resolve paths only from a list the session itself produced — a whitelist by construction, not a prefix check.
  • Every subprocess call is list-form. No shell=True, no eval, ever.
  • Static files come only from WEB_DIR + os.sep (the trailing separator matters).
  • No outbound network calls, no external assets. Keep it airgap-clean.
  • MCP config is never echoed: env, args and URLs carry API keys, so only a server's name and status are returned.

Standing battery, before every push: unauthenticated request to every endpoint → 401; path traversal raw and URL-encoded → 404; injection into model / mode / key / resume / target → 400; malformed, oversized and non-object bodies → 400.

Testing

python3 scratch/server-test.py   # pure functions, no tmux, no network
node    scratch/render-test.js   # app.js in a vm with a DOM stub

Both are plain scripts with no framework. The render harness runs app.js in a vm context; note that top-level const/let are not on the vm global, so assign them by running code inside the same context.

There is no headless browser here. Verify sprites by dumping them as ASCII grids and colours by computing contrast ratios — both are done throughout the tests. Never claim a visual change works without looking at something.

The mascot

Every axis encodes something real. Sprites are pixel maps in app.js on an 18×16 grid.

body colourgit repo (or the folder, outside a repo) — worktrees of one repo share it
hatthe model: wizard / crown / poet / kitsune = Fable / Opus / Sonnet / Haiku
held itemgit branch; main always gets the fairy wand
eggno reply yet, so the model is unknown

Hats occupy rows 0–3 (a few reach lower); items sit at x0–2 or x15–17, so the axes cannot collide. Eyes are drawn before hats so a hat can cover them. Items get an automatic dark rim (haloOf) — that is what keeps a pale item readable on a pale card. Colours and items are assigned, not hashed: the hash picks a preferred slot and collisions probe forward, because 8 keys in 8 slots collide 99.8% of the time.

Hard-won knowledge

  • User turns are not always strings. Some are [{"type":"text"}] lists. Both parsers handle that; tool results stay excluded.
  • Dialogs must be read from the pane, not from hooks. Detection accepts a ❯ cursor, an "Esc to cancel" line, or a yes-ish option — requiring "yes" made every AskUserQuestion menu invisible.
  • The mode footer is not the last line. Trailing rows ("/clear to save 488k tokens", the sub-agent roster) sit below it, so scan the last few lines upward.
  • The composer is not the last line either — it is the bottom-most ❯ line. Past user turns use the same marker.
  • Transcript mtime is not activity. Claude Code rewrites untimestamped bookkeeping records; sort on the newest timestamped record instead.
  • A Task sub-agent's tool_use is only written once it finishes. Live ones come from the pane's agent roster (● main / ◯ type).
  • tmux daemonises, so a spawned session's process parent is the tmux server. Lineage must be recorded while both sessions are alive.
  • A transcript record can be larger than any fixed head window (one starts with a 205 KB line). Read by lines, not bytes.
  • /proc/<pid> mtime is not process start time. Use field 22 of /proc/<pid>/stat plus uptime.
  • >> is a signed shift in JS. Hashes past 2³¹ go negative and index arrays with -3. Use >>>.
  • input[type=number].selectionStart is null, so restoring a caret sends it to 0 and reverses typing. Do not rebuild a focused control at all.
  • Same-specificity CSS is decided by file order. .mascot silently overrode .legend-pet for weeks. Use .mascot.legend-pet.
  • Agents on another host are invisible to /proc and tmux. A session inside srun shares ~/.claude only; it is surfaced read-only.

Rendering rules

The poll rebuilds the board constantly, and replacing innerHTML destroys every piece of DOM state inside it — scroll positions, open <details>, text selection, the caret. So:

  • compare the markup first and skip the write entirely when nothing changed (lastBodyHtml, lastGridHtml);
  • never rebuild a container while it holds the focus or a live selection;
  • update results in place rather than re-rendering controls the user is typing into;
  • keep exactly one scroll container per view — a scrollable box nested in a scrollable panel traps the wheel and loses its position.

Working agreements

Minimalism, modularity, cleanliness, efficiency, safety. Prefer deleting to adding, keep data-driven tables over branching code, and run the dead-code sweep (unused JS/Python functions, unused CSS classes) plus the security battery before every push.
